# Bevy 0.19 → 0.20 checklist

Source-backed review of the official [release notes](https://bevy.org/news/bevy-0-20/) and [migration guide](https://bevy.org/learn/migration-guides/0-19-to-0-20/). This is a task checklist, not a runtime compatibility certification or an exhaustive replacement for the guide. Resolve exact destination versions and review every guide section affecting the project.

## Dependencies and features

- Check third-party plugins (including Avian), platform targets, and lockfile compatibility independently of Bevy's release.
- WESL is always enabled; remove the obsolete `shader_format_wesl` feature. GLSL support is removed; plain WGSL without preprocessor directives still works.
- Extraction infrastructure moves to `bevy_extract`; shape and curve modules split into `bevy_shape` / `bevy_curve`. Match imports and enabled features to destination source.
- `compressed_image_saver` now selects BCn/ASTC compression with mip generation. Use `compressed_image_saver_universal` to retain Basis Universal/UASTC behavior for cross-platform transcoding.
- DLSS users must install the updated SDK; inspect supported adapters and distribution requirements.

## BSN and initialization

- Prefix every scene inclusion with `@`, including variables, functions, and `@{expressions}`. Component values and chained methods need no `template_value` wrapper.
- Replace comma/parenthesis entity-list separators with `--`; use brace-delimited `bsn! {}` / `bsn_list! {}` macro invocations.
- Enums with `Default + Clone` no longer need `VariantDefaults` / `FromTemplate`; specify every variant field.
- Use `On<Ready>` for spawned-scene logic that needs descendants and initial components. Keep glTF/legacy scene readiness and GPU pipeline readiness independently verified.
- Treat .bsn asset authoring, assets-as-entities, and the other “What's Next” items as roadmap work, not guaranteed shipped APIs.

## ECS, scheduling, and errors

- Lifecycle observer bundle filters move inside the event: `On<Add<T>>` replaces `On<Add, T>`. Dynamic component patterns use `On<Add<()>>`; custom bundle-filtered events follow the guide's `EventPattern` migration.
- Many-entity query iterators yield `Result`. Handle failures or deliberately use `.matched()` for skip semantics; check sorted and parallel variants separately.
- Use `NextState::set_if_different` / `CommandsStatesExt::set_state_if_different`. This differs from component/resource `Mut::set_if_neq`, which keeps its name.
- Weak ordering (`chain_weak`, `before_weak`, `after_weak`) now appears in built-in render/extraction/UI sets. Restore strict edges for dependencies hidden in channels, atomics, globals, or read-only interior mutability.
- With `debug`, `ScheduleBuildSettings` gains `shuffle_seed`. Replay logged seeds and retain ambiguity checks; deferred sync placement and multithreaded execution limit shuffle coverage.
- Panics route to the fallback error handler; the default re-panics. Verify custom log-and-continue policies cannot silently pass tests or leave invalid state. Use `ContextExt` for actionable errors.
- Consider column `summary_tick` and bulk `despawn_all` only with workload measurements; verify state-scoped cleanup.
- Low-level ECS/reflection users must review `ComponentInfo::id` removal, safer `ComponentId` constants, `Access` renames, `DeferredWorld::query` deprecation, `FilteredResources` deprecations, pointer/reflection casts, `CreateTypeData`, and fallible `PartialReflect::to_dynamic`.
- Settings groups now require `Resource + Reflect + Default` and appropriate reflected type data. Runtime-created `Name` values need owned strings rather than borrowed non-static strings.

## Shaders and rendering

- Convert naga_oil-preprocessed shaders to `.wesl`. Rewrite imports with semicolons at the start of the file, path-based module names, declaration/statement-attached `@if` conditionals, and `constants::NAME` definitions.
- Remove `#define_import_path`. Embedded module paths follow crate/file paths; update registrations, imports, and asset URIs together.
- Check moved shader helpers (including octahedral encoding), material bindings (`BindGroupBuilder` replaces `UnpreparedBindGroup`), typed/aligned `ShaderBuffer` data and explicit GPU sizes, and depth/stencil attachment changes.
- Mesh bounds use `MeshAabb::get_aabb`, not `compute_aabb`; `MeshTag(x)` becomes `MeshTag::new(x)`.
- `ScreenSpaceTransmission` is now opt-in on `Camera3d`. Restore it explicitly only where screen-space specular transmission is required.
- `Tonemapping` and `DebandDither` move to `bevy_render::view`; `Tonemapping::None` becomes full passthrough. Compare color-managed captures.
- Camera stacks share `ResolvedCompositingSpace`; conflicting requests fall back to linear with a warning. Mixed-HDR upper-camera blits now composite automatically; explicit write blend state can preserve replacement behavior.
- Extraction traits specify target app labels, such as `#[extract_app(RenderApp)]`. `TemporaryRenderEntity` uses `default()`. Window data becomes queried `ExtractedWindow` / `SurfaceData`; custom render channels need the shared `MainThreadExecutor`.
- UI extraction is retained. Custom UI render code must consume changed-node tracking and migrated extracted data/clipping rather than assuming nodes respawn every frame.
- Sprites use the unified mesh/material backend and default blend alpha mode. Give overlapping sprites explicit Z levels; same-Z ordering may change. New sprite extensions use `MaterialExtension2d`, `SpriteMaterial`, and `SpriteMaterialPlugin`; the old internal types become `SpriteMeshMaterial` / `SpriteMeshMaterialPlugin`. 2D mesh extensions use `ExtendedMaterial2d`.
- Solari ReSTIR is off by default; re-enable `SolariLighting::restir` if quality requires it. Verify atmosphere/environment-map lighting and moving shadows. macOS Metal is supported but has no built-in Solari denoiser. Point/spot/rect light support is not established by these release notes.
- New mesh-shader integration is advanced and unsupported on web; it is not a turnkey `StandardMaterial` path. CAD controls can use `PanOrbitCamera` with its plugins and mesh picking; check duplicate plugin registration.

## UI and input

- Replace `Pointer<Press>` with `PointerPress` and other generic pointer events with their flat equivalents. Use `pointer.id`, `pointer.position`, and `pointer.location()` for target metadata.
- Legacy UI `Button` / `Interaction` are deprecated in favor of `ui_widgets::Button`, `Hovered`, and `Pressed`. Follow the updated button example and exercise picking/focus.
- Text inputs require both `EditableText` and `TextInput`; viewport replaces `TextScroll`. Escape releases focus and propagates; test parent cancel/close behavior.
- Default text size becomes `FontSize::Rem(1.)`. `Val::Em` / `Val::Rem` and UI transform/value resolution need `EmSize` / `RemSize`; app code owns font-size propagation.
- `BorderRadius` fields become `CornerRadius`, resolved radii become `Vec2`, and `CalculatedClip` holds transformed rectangles or `FullyClipped`. Test hit areas in physical coordinates.
- `FixedNode` escapes parent layout/clipping/transform context to the target viewport. Inline boxes/images change text traversal; review custom `TextReader`, font loading/source APIs, and removed font-source resolution.
- Tabs emit externally applied `ValueChange<Option<Entity>>` requests; apply them in the app or attach `tablist_self_update`. Headless widgets mean unstyled behavior, not a windowless renderer.
- Feathers adds color/list/dropdown/lazy-menu widgets and number scrubbing; updates use `NumberInputValue`. Theme customization now resolves semantic tokens with `ThemeContext`. Check changed color-plane orientation, cursor module location, and focus causes when relevant.

## Evidence required

Compile the changed targets/features, then run real asset-loading, input, state, and renderer-backed scenarios. Load every migrated shader at runtime. Compare transmission, sprite overlaps, camera stacks, font scaling, and teardown against the baseline; record which new defaults were intentionally adopted.

The collection's bundled smoke crate remains pinned to 0.19.1. Its historical or fresh success establishes that version's infrastructure only, not Bevy 0.20 compatibility.
